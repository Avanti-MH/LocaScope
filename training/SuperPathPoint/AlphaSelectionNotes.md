# Alpha 校準——怎麼選出一個好 alpha

`plan.md` 2.2① 的前置分析。這份記錄的是**推導過程**——從哪裡開始想、中間推翻了
什麼、最後停在哪個還沒解決的問題上。決定下來的東西才會回填進 `plan.md`；這裡是
過程,不是結論。

---

## 0. 起點：`tau = max(tau_floor, alpha * ds)`

`alive[j] = (score[j] > score_threshold) & (0 <= dist[j] <= tau[j])`
（`Patterns.alive_from`）。alpha 是一個全域純量,同時乘上 5 個 rung 的 ds,決定
每個 rung 的容忍距離。alpha 越大,tau 越寬,越多本來判死的 rung 會被判活。

---

## 1. 第一次嘗試：從 margin / gap 這兩條曲線挑

實測 `alpha_curve_C.csv`（10 棵 ChainStack 聚合，`BRACS_1228`）：

- **margin**（`match_rate / decoy_rate`）在每個 rung 都**單調遞減**——alpha 越
  小 margin 越大（ds=1：alpha=0.5 時 188，alpha=4 時剩 3.9）。當選擇標準沒有意
  義,永遠選到掃描範圍的邊界,選不出中間值。
- **gap**（`match_rate - decoy_rate`）在 ds=1 也是單調遞減（match_rate 早就飽
  和在 0.815 附近,加大 alpha 只會拉高 decoy_rate),但 ds=2/4/8/16 都出現**中間
  的極大值**,而且極大值對應的 alpha 隨 rung 變粗往右移（ds=2≈2.25、ds=4≈
  3.25、ds=8≈3.5、ds=16≈3.5-3.75）。

**卡住的地方**：alpha 是全域值,同時套在 5 個 rung 上,但每個 rung 的 gap 極大
值不一樣——要用「總和」「平均」還是「保底最差 rung」在 5 個 rung 之間收斂成一
個 alpha？這題目前沒解。

**gap 最大化這個準則本身怎麼來的**：不是這幾輪臨時想的,是專案既有原則的直接推
論——`spec.md 1`（`NullModel.py` docstring 引用)：「every criterion in this
project is a margin over a decoy」。`gap = match_rate - decoy_rate` 本身就是
這個 margin,只是這次的引數是 alpha。「選 gap 最大的 alpha」= 把這條既有原則套
用到「怎麼選 alpha」這件事本身。數學上這等同 ROC 分析裡的 Youden's J 指標
（TPR − FPR 最大化）——專案自己推出跟統計學標準做法一致的東西,不是巧合,是因
為兩者都在問同一個問題。

---

## 2. 六種樣態：alpha 真正在動的是什麼

`Patterns.classify`（`SurvivalAnalysis/Patterns.py`）把一個點的存活向量
`alive[L]`（finest first）分成六類：

| 樣態 | 條件 | ASCII |
|---|---|---|
| 一直存活 | j_lo=0, j_hi=L-1 | alive-everywhere |
| 細部存活 | j_lo=0, j_hi<L-1 | fine-only |
| 晚生型 | j_lo>0, j_hi=L-1 | late-born |
| 只在一階 | j_lo=j_hi | one-rung-only |
| 中間帶 | 0<j_lo≤j_hi<L-1 | mid-band |
| 不連續 | 不是連續帶 | flicker |

前五種是「帶子」（alive 向量裡連續一段 True，前後都是 False）；不連續不是帶
子。**alpha 變大 → tau 變寬 → 更多 rung 從死翻活 → 帶子被撐寬、缺口被填平**：
不連續可能因為中間那個死掉的 rung 被撐活而變成一個連續帶；任何一種帶子（一直
存活、細部存活、晚生型、只在一階、中間帶）都可能被撐進另一種帶子。alpha 拉到
極端時,tau 趨近無限大會讓每個 rung 都判活,這是唯一的吸收態,所以形式上六種樣
態最終都會被吸收進一直存活——但這只是 alpha 趨近極端時的數學極限,不代表分析
現階段已經把一直存活當成目標或特別看重的樣態。

**這是使用者提出的關鍵疑慮**：alpha 太大會不會把某個樣態併吞掉,讓分類看起來
更乾淨、實際上丟失了原本存在的區分？——會，這是分類規則的直接後果,不是猜測。
六種樣態裡，除了「不連續」相對不重要之外，其餘五種目前同等重要，沒有哪一個是
「正確答案」；這裡的分析階段只是先講清楚 alpha 對存活向量形狀的機械效應,不是
已經預設要保住哪個特定樣態。

## 3. 兩個既有數字分別對應哪個風險

- **decoy_rate / margin 上升** = 「假活」風險的量化證據。decoy 是刻意偏移到不
  該匹配的位置,任何 decoy 的匹配都百分之百是假的——decoy_rate 隨 alpha 上升,
  就是「tau 已經寬到連不相干的位置都判活」的直接測量,跟樣態塌縮同源。
- **offset_quantiles_of**（真實匹配距離的分位數，跟 alpha/tau 完全無關,純粹
  是資料本身的性質）= 「假死」風險的參考下限。如果選的 tau 比某個 rung 真實
  offset 的中位數/90 分位還小,那一部分「死掉」根本不是沒偵測到,是門檻定得太
  緊把真實匹配砍掉。

**已經做的事**：把 alpha 掃描的 `tau = max(tau_floor, alpha*ds)` 線族疊到
`heatmaps_<axis>.png` 的 offset 分位數 panel 上（`_plot_heatmaps`,
`cli/survival_alpha_analysis.py`）——現在可以直接看某條 alpha 線有沒有切到
q0.5/q0.9/q0.99 曲線下面,不用心算。

**還沒做的事**：offset 目前只是「視覺輔助檢查」,還沒變成一個會擋掉候選 alpha
的硬性條件。

## 4. 六樣態分布隨 alpha 變化：畫得出來,但看不出因果

`Patterns.classify` 吃的 `dist`/`score` 跟 `alpha_curve` 吃的是同一份資料
（`probe_real`/`probe_decoy` 的輸出,形狀 `[N_anchors, L]`)，只是消費方式不同:
`alpha_curve` 把它廣播成一個純量比率,這裡要對每一列呼叫一次`classify`,數六種
樣態各佔幾成。

**盲點**：alpha 變大同時做兩件事——修正一個原本因 tau 太緊而被誤判死亡的真點
（好事）、讓一個本不該匹配的東西被放寬後的 tau 撿到（壞事）。這兩件事在六樣態
分類上長得一模一樣,都是「帶子變寬、不連續變少」。分類器沒有 ground truth,單看
真實資料的六樣態分布**分不出來**是哪一種。

**延伸想法**：對 decoy 錨點也跑一次六樣態分類。decoy 理論上不該有任何合法的寬
帶結構,如果 alpha 上升時 decoy 自己的樣態分布也開始長出寬帶,那是純粹的假活證
據——這比 `decoy_rate`（純量,只問「有沒有匹配到」)更貼近「樣態被併掉」本身
（問「匹配到的形狀像不像一個合法樣態」）。

---

## 5. NullModel：把「rung 互相獨立」這個假設寫成可以算的東西

`SurvivalAnalysis/NullModel.py`。核心函式 `null_patterns(alive_rate)`:

**輸入**：`alive_rate[L]`——每個 rung 自己的邊際存活率（`alive_rate_of`=
`alive[:, j].mean()`，對每一欄單獨平均，丟掉 rung 之間誰跟誰同時活著的資
訊)。

**演算法**：假設 L 個 rung 互相獨立、各自照自己的邊際存活率丟銅板。窮舉全部
`2**L` 種存活組合,每種組合的機率 = 各 rung 貢獻相乘（活的乘 rate[j]、死的乘
1-rate[j]）。用 `Patterns.classify` 判斷每種組合屬於哪個樣態,把機率累加進對
應桶子。跑完全部組合後,丟掉「全死」那個桶（真實資料的表裡不會出現這一列)、
重新歸一化,得到 `null`——「假設完全獨立,這些邊際存活率會長成的六樣態分布」。

**為什麼用窮舉閉式解,不用 decoy**：`2**L` 在 L=6 時只有 64 種,窮舉沒有抽樣誤
差,不用真的跑一次;而且 null 是拿**實測**的邊際存活率去算,不是假設 50/50,所
以「帶子比預期多」講的是**結構**（跨尺度相關性）不是**密度**（到處都活,帶子
自然多,跟結構無關)。

**已知偏差**：null 沒有建模、也不該建模的東西是「rung 之間的獨立性」——這正
是被測試的假設本身。但相鄨 rung 讀的是重疊、相似細節的組織,就算圖像完全沒結
構,相鄰 rung 的偵測本來就會有點相關——null 因此**低估**了純粹湊巧該有的帶子
比例,小幅度的 excess 不能當證據。

### 具體算一遍（L=3，方便手算）

假設量到 `rate = [0.8, 0.5, 0.3]`（細、中、粗）。窮舉 8 種組合：

| 組合(細,中,粗) | 機率 | 判定 |
|---|---|---|
| F,F,F | 0.2×0.5×0.7=0.07 | 空 |
| T,F,F | 0.8×0.5×0.7=0.28 | 只在一階 |
| F,T,F | 0.2×0.5×0.7=0.07 | 只在一階 |
| F,F,T | 0.2×0.5×0.3=0.03 | 只在一階 |
| T,T,F | 0.8×0.5×0.7=0.28 | 細部存活 |
| T,F,T | 0.8×0.5×0.3=0.12 | 不連續 |
| F,T,T | 0.2×0.5×0.3=0.03 | 晚生型 |
| T,T,T | 0.8×0.5×0.3=0.12 | 一直存活 |

扣掉「空」的 0.07、重新歸一化（÷0.93）：

`null = {一直存活:0.129, 細部存活:0.301, 晚生型:0.032, 只在一階:0.409,
中間帶:0, 不連續:0.129}`

假設實測 `measured = {一直存活:0.35, 細部存活:0.25, 晚生型:0.05,
只在一階:0.20, 中間帶:0, 不連續:0.15}`。`excess = measured - null`
是**六個樣態各自對應相減**（不是矩陣運算）：

| 樣態 | measured | null | excess |
|---|---|---|---|
| 一直存活 | 0.35 | 0.129 | **+0.221** |
| 細部存活 | 0.25 | 0.301 | -0.051 |
| 晚生型 | 0.05 | 0.032 | +0.018 |
| 只在一階 | 0.20 | 0.409 | **-0.209** |
| 中間帶 | 0 | 0 | 0 |
| 不連續 | 0.15 | 0.129 | +0.021 |

六個 excess 加總必為 0（measured、null 各自加總都是 1）。讀法：一直存活比純
機率預期多 22 個百分點,只在一階比預期少 21 個百分點——rung 之間存在**正相
關**,不是各自獨立丟銅板湊出來的結果。excess 全部接近 0,代表 measured 只是
邊際存活率的機械結果,沒有額外的結構資訊。

## 6. 為什麼 excess 可能是比 gap 更好的目標（本節的結論後來被 Q7 推翻，見附錄）

`alive_rate`（null 的輸入）本身是 tau 的函數,tau 又是 alpha 的函數——**alpha
一變,不只 measured 會變,null 也會跟著用新的邊際存活率重算**。excess 抓的正
是「扣掉純粹因為存活率變高而自動撐出來的帶子之後,還剩下多少是 rung 之間真正
相關的結構」。

`Patterns.py` 自己的 docstring 提到:spec.md 3.3 另外用「多少比例的點是帶子」
這個數字決定 Stage C 的頭能不能簡化——這是一個**已經存在、屬於別的決策**的事
實,提在這裡只是說明核心任務（六樣態分類本身）交出去的東西會被下游拿去用,不
是說這次選 alpha 就是要去優化「帶子比例」這個特定數字,也不代表六個樣態裡哪一
個比較該被留住。excess 這個角度真正對齊的,是「六樣態分類本身有沒有承載真實
資訊」這個更一般的問題,不特別偏袒帶子或哪一個樣態；gap則是側支alpha校準自己
的內部一致性指標,問的是「這個rung的match有沒有贏過decoy」,逐rung的匹配品質
問題,跟核心任務隔了一層。

**推論 excess-vs-alpha 大機率也有一個峰值,原因跟 gap 的峰值不同**：

- alpha 太小:粗 rung 邊際存活率接近 0,「大家同時活著」在 null 底下本來就罕
  見,就算真結構存在也還沒機會被量出來（跟 offset 的「假死」是同一件事的另一
  種呈現)。
- alpha 太大:所有 rung 邊際存活率被推向 1,null 自己也預測「幾乎全部一直存
  活」,measured 跟 null 一起逼近同一天花板,excess 被壓縮到 0（跟 decoy_rate
  上升的「假活」是同一件事的另一種呈現)。
- 中間某處:存活率夠高、樣本夠多讓相關性有機會顯現,但還沒高到讓純機率自己就
  已經預測「大家都活著」——這裡應該是 excess 的真正峰值。

**交叉驗證**:同一套 excess 計算,也對 decoy 錨點跑一次。decoy 不該有真結
構,如果 decoy 自己的 excess 也隨 alpha 明顯偏離 0,代表抓到的相關性不是真點
的結構,可能是 decoy shift 建構方式本身的系統性偏差。**好 alpha = 真實
excess 在峰值,同時 decoy 的 excess 維持接近 0。**

## 7. gap 最大化本身沒解決的問題（不代表 excess 就沒有）

1. 跨 rung 怎麼收斂成一個 alpha——sum/mean/worst-case,還沒選。excess 面對的
   一樣是全域 alpha 的問題,這題不會因為換了目標就自動解決。
2. 忽略不確定性——`gap_std`（10 棵樹的 C 軸樣本量不大）沒有被用來檢驗峰值是
   不是顯著。excess 一樣需要考慮跨樹的變異,不是單一個 `excess` 數字就夠——
   附錄 Q5 有具體做法（卡方/G 檢定 + ChainStack 層級的 bootstrap）。
3. offset/decoy 目前只是「附帶效果」,不是明確的硬性篩選——提議：先用 offset
   分位數擋掉「tau 低於 q0.5/q0.9」的 alpha（假死),再用 decoy_rate 或
   decoy-excess 擋掉「已經在製造假活」的 alpha,剩下的候選裡才談 gap 或
   excess 最大化。
4. `classic_region` 的前車之鑑（`ClaudeRules.md`）:固定門檻在不同 WSI/不同
   位置差 2 倍,特徵被整個拿掉,不是重新校準——好 alpha 或許要找的是「所有
   rung 都還算不錯的穩定平原」,不是單一尖銳峰值,以換取跨資料集的穩健性。

## 8. SIFT 特徵尺度：這整個分析的起源，以及它給 alpha 一個新的估計角度

這個分析的動機來自 SIFT：SIFT 建尺度空間金字塔、在 DoG response 上找極
值，找的方式是在 `(x, y, scale)` 三維空間裡找局部極值——一個候選點要跟同尺
度、上一尺度、下一尺度共 26 個鄰居比，才算數。這代表 SIFT 從骨子裡假設：**
一個特徵有沒有資格當關鍵點是尺度的函數，每個特徵有自己的「特徵尺度」，在那
附近 response 最強，離開太遠就變弱、甚至消失。** 六種樣態的假設（同一塊組織
在不同解析度下，有些 keypoint 只在細、有些只在粗）是這個理論的直接推論，不
是憑空湊出來的分類。

**我們現在的 `alive` 判準比 SIFT 真正的判準粗糙**：SIFT 問「這是不是相對於
鄰近尺度的局部極值」（比較性測試）；我們問「這個 rung 自己，分數夠不夠、離
錨點夠不夠近」（兩個獨立的固定門檻，跟鄰近 rung 無關）。這個差距本身就是候選
2（尺度局部極值法，見第 10 節）的動機。

**由此給出一個理論估計 alpha 的角度**：真實特徵在同一個位置，換到粗 rung 之
後，即使 response 仍然夠強被偵測到，粗 rung 的 tile 像素本身就對應到 level-0
一大塊區域——降採樣已經把這塊區域內的細節丟棄，偵測器不管多準，都不可能從已
經被壓扁的粗圖裡回推出比這塊區域更精細的位置。**這不是座標轉換 `to_level0`
的誤差，是粗 rung 的原始資料本身就不含那個精細度的資訊**——`tau` 隨 `ds`
線性放大，補償的正是這個「一個 tile 像素代表 ds 個 level-0 像素」的天生解析
度落差，不是特徵本身的漂移。

拿真實數字驗過（見第 11 節，會發現這個估計本身也被污染，數字不能直接信）。

## 9. offset 為什麼有時大得離譜：自我匹配與 born_rung

**錨點是各 rung 聯集，merge 用 finest-first 順序——所以一個錨點的座標，精確
複製自某一個 rung 自己貢獻的原始偵測點，不是重算或取平均。** 這帶出一個構造
上保證成立的事實：對「貢獻這個錨點的那個 rung」算距離，答案精確是 0（自己對
自己），不是「很小」。

**「貢獻錨點的那個 rung」= `Attribution.born_rung_of` 定義的 born_rung**，兩
者是同一件事：一個位置的錨點代表權，永遠落在「這個位置最細、有偵測到東西」的
那個 rung——因為 finest-first 合併順序保證更細的先贏；而 born_rung 的定義正
是「alive 向量裡最細的 True」。所以：**alive[born_rung] 對任何錨點、任何
alpha 都保證是 True**（born_rung 那格 dist=0，且該點在偵測時本來就已經清過
score_threshold）。

**這解釋了真實數據裡 `ds=1, q0.5=0.0` 剛好是精確值，不是巧合**：C 軸 finest-
first 合併下，幾乎所有在 ds=1 出現過的點，born_rung 就是 ds=1 本身——這一列
的 offset 幾乎全部是自我匹配的 0，稀釋掉了真正有意義的跨 rung 資訊。而 ds=2/
4/8/16 幾乎沒有錨點在那裡出生（因為只要 ds=1 有偵測到就搶先贏了代表權），所
以這幾階的 offset 幾乎全部是「born 在別處的錨點，來這裡做跨 rung 檢查」的真
實測量,沒有自我匹配稀釋。

**方法論後果**：`offset_quantiles_of` 目前對每個 rung 一視同仁地算距離分
布，但不同 rung 量到的根本不是同一種東西——細 rung 被自我匹配的 0 污染（低
估)，粗 rung 全部是跨 rung 真實檢查（可能被前幾節講的「附近沒有真配對、抓到
不相干東西」污染，高估)。**第 8 節那個「offset/ds 該是常數」的估計，因此不可
靠——分子在不同 rung 根本不是同一種統計量,不能跨 rung 比、更不能外推。** 正
確做法應該是算 offset 時排除掉 `j == born_rung(anchor)` 那一格，只統計真正的
跨 rung 檢查。

**2026-09-13 修掉**：`anchors_of`/`anchors_of_generations` 現在多回傳一個
`source_rung`（每個錨點的座標實際複製自哪個 rung，合併時本來就算得出來、
只是原本沒回傳），`offset_quantiles_of` 新增 `source_rung` 參數，第 j 欄排
除 `source_rung == rungs[j]` 的列，不再把自我匹配的 0 算進去。`source_rung=
None`（預設）維持修正前的舊行為，還沒接上這個參數的呼叫端不受影響。
`cli/survival_alpha_analysis.py` 的 baseline/exp_decay 路徑已經接上；
probability_map/scale_extremum 路徑本來就沒有 offset_quantiles_of 這個診
斷，不受影響。測試見 `test_alpha_calibration.py`
（`t_offset_quantiles_of_excludes_the_self_match_column`）跟
`test_survival_process.py`
（`t_anchors_of_source_rung_names_which_rung_each_anchor_survived_in`）。

**結論（使用者定案）**：不要拿 p90 offset/ds 這種數字反推 alpha（例如拉到
16 這種量級）——不適當，原因正是上述兩層污染。上面的修正解決了「細 rung 被
自我匹配稀釋」那一層；粗 rung 的「附近沒有真配對、抓到不相干東西」污染仍
未處理。

## 10. 六樣態怎麼算出來的：完整五步 + 一個結構性事實

1. **偵測**：`SurvivalProcess.detect` 在每個 rung 自己的機率圖找點，換算
   level-0 座標，存成 `per_rung_detections[ds]`。
2. **建錨點**：`anchors_of`/`anchors_of_generations` 把所有 rung 的點攤開，
   finest-first 跑 `_merge_within_radius`（網格雜湊合併法）去重，存活的成為
   錨點，帶著 born_rung（第 9 節）。
3. **逐階探測**：`probe_real` 對每個錨點、每個 rung 都算一次
   `nearest_detection`，得到 `dist[N,L]`、`score[N,L]`。
4. **算 alive**：`Patterns.alive_from(score, dist, threshold, tau)`，
   `tau[j]=max(tau_floor, alpha*ds[j])`。
5. **分類**：`Patterns.classify(alive[i,:])`。

**結構性事實**：因為 born_rung 保證 alive、且定義上是最細的 True，所以**存
活帶的起點 j_lo 永遠精確等於 born_rung**，不用另外算。六種樣態因此可以重新讀
成「born 在哪 + born 之後死不死、什麼時候死、死了會不會在更粗的地方復活」：

| 樣態 | 用 born_rung 講 |
|---|---|
| 一直存活 | born_rung=0，一路活到最粗 |
| 細部存活 | born_rung=0，中途死掉 |
| 晚生型 | born_rung>0，一路活到最粗 |
| 只在一階 | born 之後下一階馬上死 |
| 中間帶 | born_rung>0，中途死掉 |
| 不連續 | 死了之後在更粗的階又活過來 |

**這也解釋了為什麼 `Patterns.py` 說「空（全死）不可能發生」不是經驗現象，是
構造上的必然**——born_rung 那格保證 alive，全死不可能發生。而「不連續」需要
「在更粗的階復活」，復活靠的正是第 9 節那個最不乾淨的跨 rung 檢查——這可能是
它被列為六樣態裡「比較不重要」的結構性原因。

## 11. 那為什麼還需要定 alpha

born_rung 那一格不用校準就保證 alive，但其餘 L-1 格的死活全部是 alpha 決
定，而六樣態的**區別**就藏在這 L-1 格裡：

- **alpha→0**：除了 born_rung，其餘格幾乎不可能存活（tau≈0）。每個錨點都會
  被分類成「只在一階」，六樣態塌縮成一種，只回答「born 在哪」，回答不了「這
  個特徵有沒有跨尺度持續」——當初做這個分析真正想問的問題。
- **alpha→∞**：tau 大到不管多遠都算近，每個錨點都會被分類成「一直存活」，
  一樣塌縮，一樣答不出真正的問題。

**alpha 是唯一決定「六樣態分析落在這兩個無意義極端之間哪裡」的旋鈕。** alpha
設太小，系統性低估真實的跨尺度持續性；設太大，系統性高估（尤其透過「不連
續」的復活機制，把不相干的粗階配對誤判成延續）。兩種錯法都不是隨機雜訊，是
往固定方向扭曲整個六樣態分布，直接關係到這個分析成不成立。

## 12. gap（match/decoy）跟「keypoint 精度 + 粗細階誤差」的關係——使用者定案

兩把獨立的尺，量同一個目標（tau 該多寬），證據來源不同：

- **gap/margin**：行為/統計證據——用真實流程的結果（真實匹配率有沒有贏過
  decoy）反推，量到的是(A)特徵尺度衰減、(B)解析度誤差、(C)confound 的**淨
  效果**，不會拆開。
- **keypoint 精度 + 粗細階誤差**：物理/機制證據——只針對(B)，理論上不需要
  decoy、不需要跑真實流程（但第 9 節指出，目前唯一算得出這個估計的
  `offset_quantiles_of` 本身被自我匹配跟跨 rung 污染，數字不可靠）。

**使用者定案：gap 的篩選機制目前仍是最好的、主要的判準；keypoint 精度/粗細
階誤差的物理估計，用來輔助（cross-check），不是拿來取代 gap。** 如果 gap 最
大化選出來的 alpha 明顯低於物理估計給出的下限，那是 gap 那條線被什麼污染
了，要回頭查,不是各打五十大板取中間值。

## 13. decoy 目前實際用哪一種

- **decoy_kind = fixed**（`DECOY_KIND` 預設值，這次所有 run 都沒覆寫）。
  `decoy_shift_fixed` 的實際算法：`_decoy_shift_per_rung` 裡，每階位移量
  `mag = DECOY_MAGNITUDE(預設8.0) * rung_shrink(ds, axis)`，拆成對角線方
  向的固定位移 `(mag/√2, mag/√2)`——**同一階裡每個錨點被加上完全相同的
  (dx,dy)，方向大小都不隨錨點變，只隨 rung 自己的 `rung_shrink` 縮放。**
  （`random`：每個錨點各自抽獨立隨機方向/大小；`rotate`：繞錨點集合質心
  各自轉獨立隨機角度——這兩個都還沒用過。）

## 14. alive[j] 候選演算法命名（1/2/3 已經接進 sweep 在跑，4 已寫出函式但還沒接
CLI，實作都在 `AliveCandidates.py`；這裡只留公式跟取捨，完整設計見各函式自己
的 docstring）

**絕對雙門檻法**（現況，`Patterns.alive_from` / `AliveCandidates.
alive_absolute_dual_threshold`）

    alive[i,j] = (score[i,j] > score_threshold)
               & (dist[i,j] >= 0)
               & (dist[i,j] <= tau[j])

`score[i,j]`/`dist[i,j]` 是「離錨點最近的那個真實偵測點」的分數跟距離
（`SurvivalProcess.nearest_detection`）。`dist < 0` 是這一階**完全沒偵測到任
何東西**的 NONE sentinel，跟「有偵測到、只是很遠」是兩件不同的事，不能合併。
代價：稀疏區域（沒有真實偵測點可比）offset 會被撐大，污染統計。

**機率圖法**（候選1，`AliveCandidates.alive_probability_map`，需要
`probe_via_probability_map` 先算出 `peak_value`/`peak_dist`）

    步驟一（每個 anchor、每個 rung 各做一次）：
      在錨點的固定座標附近，半徑 tau[j]/scale（換算成這個 rung 自己的像素單
      位）的一個「圓」內（不是外接正方形），以 sample_step 為間距取樣候選
      點，對原始機率圖（combined_map，到處有定義，不是只有 NMS 留下的 peak
      才有值）做雙線性內插，取內插值最大的那個候選點：
        peak_value[i,j] = 該候選點的內插值
        peak_dist[i,j]  = 該候選點到錨點的距離（換算回 level-0 px）

    步驟二：
      alive[i,j] = (peak_value[i,j] > score_threshold)
                 & (peak_dist[i,j] <= tau[j])

沒有 `dist>=0` 這個 NONE 判斷——稠密機率圖只要視窗非空就一定有極大值，「這
一階什麼都沒有」在這個候選裡不存在，只會讀出一個很低的 peak_value，靠
score_threshold 一起濾掉。解決什麼：從根本解決背景污染（視窗外的東西讀不
到，不會撐大稀疏區域的 offset），同時讓候選2不再循環（同一固定座標，每階
都能直接讀值比較，不用靠「最近偵測點是不是同一個特徵」這個尚待回答的問
題）。代價：需要 `SurvivalProcess.detect_all_generations` 保留並回傳原始機
率圖（原本 `_detect_one` 把 `prob` 用完就丟），記憶體用量大幅增加；
`sample_step` 是還沒調過的精度/速度旋鈕。

**尺度局部極值法**（候選2，`AliveCandidates.alive_scale_local_extremum`，
`margin` 預設 0，一樣需要候選1的 `peak_value`/`peak_dist`）

    alive[i,j] = (peak_value[i,j] > score_threshold)
               & (peak_dist[i,j] <= tau[j])
               & (peak_value[i,j] >= peak_value[i,j-1] - margin)   （j>0 才比）
               & (peak_value[i,j] >= peak_value[i,j+1] - margin)   （j<L-1 才比）

頭尾兩個 rung（j=0 或 j=L-1）只有一個鄰居可比。`margin=0` 時這個條件有一個
**結構性後果**：要 j 跟 j+1 同時活著，代入上式會同時要求
`peak_value[j] >= peak_value[j+1]` 跟 `peak_value[j+1] >= peak_value[j]`，
唯一解是兩者位元級相等——真實浮點機率值幾乎不可能剛好相等，所以**兩個相鄰
rung 在這個判準下幾乎不可能同時活著**，六樣態會被迫塌縮成只剩「只在一階」
跟「不連續」，其餘四種（需要連續帶寬度 ≥2）在結構上被排除，不是機率上比較
少見（2026-09-11 實測 C 軸 sweep 觀察到這個塌縮）。解決什麼：真正
貼近 SIFT 原始的 26-neighbour DoG 極值判準。代價：上面這個結構性副作用；必
須搭配候選1才不循環，單獨拿「最近偵測點的 score」比鄰階，鄰階的最近偵測點
是不是同一個特徵本身就是在問的問題，會循環論證。

**指數衰減聯合分數法**（候選3，`AliveCandidates.alive_exp_decay_joint_score`）

    combined[i,j] = score[i,j] * exp(-dist[i,j] / max(tau[j], 1e-9))
    alive[i,j]    = (dist[i,j] >= 0) & (combined[i,j] > combined_threshold)

`exp(-dist/tau)` 在 `dist=0` 時是 1.0，之後平滑衰減，所以 `combined` 在零
偏移時跟 `score` 同一個尺度、其餘情況一定更小——`combined_threshold` 因此
必須遠低於 `score_threshold` 才收得到任何非零偏移的點，兩者不能互換（這也
是 CLI 要求顯式給 `--combined-threshold`、不會預設等於 `--score-threshold`
的原因）。解決什麼：把兩個獨立門檻融成一個連續分數，避免絕對雙門檻法的硬邊
界。代價：`combined` 把「完全沒偵測到」（`dist<0`，已經被 `valid` 濾掉）跟
「偵測到但很遠」混進同一個連續數字裡，這個判準本身有這個問題；跟機率圖法無
關，不會被它解決。

**雙成分混合模型法**（候選4，`AliveCandidates.alive_two_component_mixture`，
函式已寫出但沒接進 CLI/sweep）

    對每個 rung j 單獨做（用這一欄「所有」錨點的 dist[:,j]，不是逐點）：
      把 dist[:,j]（排除 NONE）的經驗分布擬合成兩個 Rayleigh 分量的混合
      （EM，_fit_rayleigh_mixture）：
        「真配對」分量 -- sigma 較小
        「背景／沒配對」分量 -- sigma 較大
      算每個點的後驗機率 P(真配對 | dist[i,j])

    alive[i,j] = (score[i,j] > score_threshold)
               & (P(真配對 | dist[i,j]) > posterior_threshold)

跟其他四個候選不同：這個不是逐 (anchor, rung) 的純函式，要先看過整欄
`dist[:,j]` 的分布才能擬合出兩個 sigma，所以是照 rung 迴圈，不是像其他候選
一樣直接吃一個純量 `tau`。解決什麼：理論上最徹底地把「真配對」跟「背景」兩
個成分分開，不用硬性 tau 切一刀。代價：最重，要選分布形狀（這裡選
Rayleigh，理由見 `_rayleigh_pdf` 自己的 docstring）、EM 擬合；C 軸每棵樹每
個 rung 各自獨立擬合，某棵樹在某個 rung 的錨點數 n<8 時 `_fit_rayleigh_
mixture` 會退化成單一分量（全部判「真」），是有文件記載的降級，不是當機，
但正是這個候選最大的風險（資料量能不能撐起穩定擬合）。

候選5（排名/分位數判準）已被排除：方向可能相反——稀疏區域反而會放寬標準,跟
想要的效果相反。

機率圖法（候選1）現在是理論上最根本的選項——直接解決背景污染，還讓候選2成
立，代價是要動`detect_all_generations`的回傳合約、記憶體用量增加，不是換一
個判準這麼簡單。雙成分混合模型（候選4）理論乾淨但代價最高，現有資料量能不
能撐住還很可疑。聯合分數法（候選3）的問題（混淆NONE）不會被機率圖法解決,
優先度較低。

候選1的完整定案設計（A/C兩步驟怎麼算、union/intersection用max/min、NONE
消失的取捨、`rival`可能變得多餘）已經寫進`AliveCandidates.py`各函式自己的
docstring，不在這裡重複一份。

## 附錄：Q&A

討論過程裡使用者直接追問、逐條釐清的部分，按問題整理，不重複正文已經講過的推
導。**不引用 docstring 當作理由本身**——docstring 只是線索，下面每題都是重新
從頭推一次。

**Q1. 為什麼 null 不建模 rung 之間的相關性——是文件這樣寫，還是有更根本的原
因？**

不是「文件這樣講」的問題，是定義上就只能這樣。null 的輸入只有邊際存活率（每
個 rung 自己的 `P(alive)`），完全不包含「誰跟誰同時活著」這個聯合資訊，結構上
就只能描述「假設完全獨立」的世界。如果要讓 null 去建模真正的相關性，那相關性
這個參數要從哪裡來？只能從實測的聯合分布本身估——但那正是要拿來跟 null 比較
的東西。用測到的相關性去建構「拿來檢驗有沒有相關性」的基準，是循環論證，基準
會直接等於答案。所以 null 只能建立在比聯合分布更弱、更簡單的統計量（邊際率）
上，刻意對「有沒有相關性」保持無知——這樣任何偏離 null 的地方，才有資格被歸
因給「相關性」這個效應，不是循環地把答案塞進基準裡。

**Q2. 是不是因為 null 假設 rung 彼此獨立，但有跨尺度結構的 keypoint 就不獨
立了？**

對。假設一個真正跨尺度都看得出來的組織特徵，它在 rung 1 有沒有被偵測到、在
rung 2 有沒有被偵測到，兩者的成因是同一個——都是這個特徵本身夠獨特、夠穩
定。所以 `P(rung 2 活著 | rung 1 活著)` 會大於 `P(rung 2 活著)` 本身，這就是
正相關。反過來，一個純粹巧合的雜訊匹配，沒有理由「剛好也」在另一個 rung 超過
門檻，那種情況才長得像獨立丟銅板。**真結構在數學上等於打破獨立性，這是同一件
事的兩種講法，不是巧合。**

**Q3. 怎麼確定真的有相關性，是不是要檢驗機率符不符合獨立事件的定義？**

對，這正是標準做法——**卡方或 G 檢定**：`null_patterns(alive_rate) * N` 當
六個樣態的期望次數，真實分類出來的六個樣態實際次數去比對，算 goodness-of-fit
統計量，得出一個 p 值。p 值夠小才能說這個偏離不太可能只是抽樣噪音。**陷阱**：
同一棵樹裡的 N 個錨點彼此不是獨立樣本（空間相鄰、可能共享同一塊組織），把所有
樹的錨點倒在一起用總 N 算卡方，會低估真正的不確定性、讓 p 值看起來比實際更顯
著。比較誠實的做法是在 ChainStack 層級：每棵樹自己算一個 excess，10 棵樹（C
軸）當作獨立重複，用跨樹的變異去 bootstrap 信賴區間，不是相信單一個用全部點
數堆出來的卡方值。

**Q4. 除了「相鄰 rung 讀到相似組織」，還有哪些機制可能讓 excess 為正？這些機
制是不是「不代表真跨尺度結構」的 confound？——這一題原本的答案是錯的，見
Q7。**

使用者提出五個候選機制：1. 相鄰 rung 讀到重疊、相似的組織；2. 降採樣本身是平
滑、相關的變換；3. 偵測器對某些區域系統性地比較有信心（染色濃度、組織密度、
亮度）；4. 局部候選點密度效應；5. 樣本數太小的抽樣噪音。原本把 1-4 全部當成
「decoy 該濾掉的 confound」，這個框架本身錯了——見 Q7 的修正。5（樣本數太
小）維持原判斷，是抽樣噪音，跟 1-4 性質不同，這題無爭議。

**Q5. total variation（`0.5 * sum(|excess|)`）為什麼要乘 0.5，拿掉正負號之
後還有什麼用？**

`measured`、`null` 各自加總都是 1，六個 excess 加總必為 0——正的部分跟負的
部分絕對值相等、互相抵銷，所以 `sum(|excess|)` 永遠是「正 excess 總和」的兩
倍。乘 0.5 把它壓回標準 total variation distance 的定義，讓數字落在
`[0,1]`，直接讀作「最多需要搬動多少比例的機率質量，才能把一個分布變成另一個
分布」。它是**導航工具，不是診斷工具**：掃過所有 alpha 快速看哪個整體偏離
null 最遠，或者比較真實跟 decoy 誰的整體偏離幅度大，一個數字比六對線好比。侷
限是兩個分布可能算出一樣的 TVD、但 excess 分散在完全不同的樣態上（例如一組是
「一直存活+0.2、只在一階-0.2」，另一組是「不連續+0.2、細部存活-0.2」，TVD 一
樣但意義天差地遠）——TVD 只能當「先看哪裡」的粗篩，細節解讀還是要回到六條有
號線。**決定**：加這條線。

**Q6. 六種樣態裡是不是「一直存活/帶子」特別重要？**

不是，這是本文前面幾節敘事上的偏差，已經改寫。六種樣態裡除了「不連續」相對不
重要，其餘五種（一直存活、細部存活、晚生型、只在一階、中間帶）目前分析階段同
等重要，沒有預設哪個是目標。之所以會一直提到「alpha 夠大時塌縮成一直存活」，
只是因為 tau 趨近無限大時它是唯一的數學吸收態，不代表這個樣態本身比其他四種
更該被保護。

**Q7. Q4 的「confound」框架錯在哪，excess/decoy 這條線最後定位成什麼？**

原本把機制 1（相鄰 rung 讀相似組織）、2（降採樣本身相關）、3（區域訊心度
高）當成「跟真結構分開、decoy 該濾掉的東西」，這個二分法本身錯了。一個真正
跨尺度穩定的特徵，唯一的顯現方式就是「降採樣後這塊內容還認得出來」——這正是
機制 1/2/3 同時發生的樣子，沒有一個更純粹、不經過 1/2/3 就能顯現的「跨尺度穩
定」存在。所以「有沒有相關性」本身問錯了問題：金字塔結構保證 rung 之間本來就
會相關，這是設計，不是意外，跟這個點是不是真結構無關。

順著這個修正往下想「decoy 到底在測什麼」，曾經推到「這個多階存活是精確釘在
一個座標上，還是整片鄰域都差不多」這種**精確度/局部性**的區分——**這一步
先不算數，是未經證實的推論，不是結論**。使用者明確指出：無法判斷這段有沒有
道理，而且這個推論本身可能還會被推翻，所以不能拿它去推翻更早、還沒被真正駁
倒的假設「好 alpha = 真實 excess 在峰值，同時 decoy excess 維持接近 0」。這
個假設**仍然是活著的、未決的候選**，不是被 Q7 前半段（1/2/3 不是 confound）
連帶推翻的東西——1/2/3 的修正只推翻了「decoy 用來分辨真假」這個說法，不代表
「用 decoy 監控 excess 有沒有異常升高」這件事本身是錯的。

**目前站得住腳、不需要等這條線分出勝負就能用的，是另外兩個獨立判準**：
- **offset 分位數**（下限，太緊的證據）——只用真實匹配到的距離分布，不牽涉
  decoy 或 excess。
- **decoy_rate（原始版本，不是 excess 加工過的版本）**（上限，太鬆的證
  據）——decoy 定義上不該匹配到任何東西，只要它匹配到了，不管背後是哪個機
  制，都直接是「tau 已經寬到讓不該中的東西中了」的證據，不需要先判斷 1/2/3
  誰真誰假。

這兩個判準夠獨立、夠站得住腳,可以先拿來用；excess/NullModel 那條線（六樣態
分布 + decoy excess 監控）**繼續保留成第三個候選判準,還沒有被證明有效或無
效**，第 8 節從 SIFT 特徵尺度的角度重新想了一次,不是要否決它。gap 在
offset/decoy 這兩個界線之間的極大值，是目前唯一定案的候選 alpha 挑法；六樣
態分布/excess 的圖還是要畫，是否也拿來當第三個判準，留待第 8 節之後再定。
